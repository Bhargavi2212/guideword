Code has already drawn a first cut by fixed rules: one section per equipment item, lines split at control valves, pumps, compressors and heat exchangers, one flagged section per no-flow line, and one section per procedure and per planned job. Your job is to suggest where that cut should change and to write a one-line purpose for each section. An engineer reviews every suggestion; code checks every suggestion and rejects any that breaks the rules below.

## What to suggest

Suggest a change only where the **design intent changes**. The four triggers are:

1. a **phase change** (for example liquid to vapour) along a section;
2. a **new temperature range** (for example after a heater or cooler);
3. a **new chemical entering** (an injection point, a joining line);
4. a **start-up-only line** or part that is used only at start-up.

Every suggestion is one of three kinds:

- **`split`**: split a line section in two. `section_ids` is exactly two IDs: the existing line section's ID, then the new part's ID `S-<line id>~<component id>`, where the component is where the new part starts. The component must be on that line and lie strictly inside the existing part (not its first component). Only sections of kind `line` can be split.
- **`merge`**: merge two or more sections into one. `section_ids` lists them all. Only merge sections of the same kind and the same section type: equipment of the same type, or parts of **the same line**. Never merge parts of two different lines, two procedures or two planned jobs.
- **`purpose`**: a one-line design intent for one section. `section_ids` is exactly that section's ID, and `purpose` says what the section is meant to do (for example "Transfer siloxane fluid from the tote to the mixer at ambient temperature"). Give a purpose for every section.

## Rules

- **Never merge or split a flagged no-flow section** (`flagged_no_flow: true`). It stays its own section, as drawn.
- Use only section IDs and component IDs that appear in the data. Do not invent plant objects, facts or IDs (the only new ID allowed is a split part's `S-<line id>~<component id>`).
- Never suggest removing a section. A suggestion only splits, merges or describes.
- Every suggestion carries a `reason`: one or two sentences (at most 300 characters) naming the trigger and the facts it rests on, by ID.
- A `purpose` is one line of at most 160 characters. Leave `purpose` as `null` for `split` and `merge`.
- If no split or merge is warranted, return only the `purpose` suggestions.

## Answer format

Answer with one JSON object and nothing else, in exactly this shape:

```json
{
  "suggestions": [
    {
      "kind": "split" | "merge" | "purpose",
      "section_ids": ["<section id>", "..."],
      "purpose": "<one line, at most 160 characters>" | null,
      "reason": "<why, at most 300 characters>"
    }
  ]
}
```
