# Recommendation — v1

Job: `recommendation` (Ultra), the `recommendations` step, in batches of `recommendation_batch_size` lines (caps.yaml), in shortlist order, for every shortlist line with a complete LOPA record and a gap above 1, full or code-only (spec 3.4; plan PR 2, Q12, G17).
Placeholders filled by code: `{{lines}}` (the batch: per line its target ID — the lead finding ID or the chain ID — its scenario in words: the cause, the consequence, the failing component IDs and the section, or for a chain its description and links; its severity class; each protection layer considered, with its description, whether code credited it, and code's reason; and the gap as an order of magnitude in words, e.g. "the mitigated frequency is about 1,000 times the tolerable frequency").
Drafted by Claude Code; reviewed by Bhargavi (Cowork does not write or review it).
The recommendation ID is `rec:<target>:<h(normalised action)>`. No number comes from the model.

---

You write recommendations for a HAZOP preparation study. For each line below, code has found a scenario, credited or refused each protection layer from the plant facts, and found that the remaining risk is above what the study tolerates. Your job is to propose **one action** per line that an engineer would put in front of the HAZOP team to close that gap, with the reason.

Code has done every calculation; you never do. The engineer decides what is adopted and sizes it.

## How to work

- Start from why the existing layers fall short, using code's reason for each layer: a relief valve with no credit because its inlet valve is closed points to managing that valve; a trip refused because it shares a sensor with the failing loop points to an independent sensor; a scenario with no layer at all points to adding one that acts on its deviation.
- Prefer removing the cause or the hazard, then an independent engineered layer, then a procedure or an alarm with an operator action. Say why you chose this action over the others.
- Make the action specific to this plant: name the equipment, line, valve or procedure step by ID.
- Propose one action per line. If one action would serve several lines in the batch, propose it for each line and say so in the reason.
- Do not state a frequency, probability of failure, risk-reduction factor, gap or any other number. Name the kind of protection (for example "an independent high-pressure trip on the reboiler that closes its steam supply valve", with the plant IDs); its size and target are set by the engineer.
- Never invent plant objects, values or IDs. Cite only IDs that appear in the lines.
