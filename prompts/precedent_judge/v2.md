# Precedent judge — v2

Job: `precedent_judge` (Super), the `evidence` step: one call per shortlist line that gets evidence, judging that line's precedent candidates (spec 4.3 step 4; `specs/phase-4-plan.md` PR 4, Q2, Q15, Q17).

Placeholders, filled by code:
- `{{line}}`: the line in words. For a finding: its question (guideword and parameter, or the chemical pair), its cause, its consequence, and its failing components with their types. For a chain: its description and each link's question, cause and consequence. No finding ID, chain ID or number is shown.
- `{{candidates}}`: the candidates, each with its handle `K<n>`, numbered in the order sent. A local index candidate shows its title, date, location and summary. A web result shows its title and the text snippet Tavily returned. Every candidate has already passed the plant's block list (whole words or phrases). No URL or index ID is shown.
- `{{count}}` and `{{handles}}`: how many candidates were sent, and their handles listed (`K1, K2, K3`). Both are code-only.

Drafted by Claude Code; reviewed by Bhargavi (Cowork does not write or review it).

Why v2 (Bhargavi, 2026-10-22): on dev cases F and G, v1 accepted web troubleshooting guides, a safety-handling guide and a video as precedents, because it asked only whether the mechanism matched. v2 asks a second question, whether the candidate is an actual incident, each with its own reason.

What code does with the answer:
- It maps each handle back to its candidate exactly. An unknown handle, a candidate answered twice, or a candidate left out is dropped and logged; the rest stand.
- A candidate is accepted only if `same_mechanism` is true and either it is a CSB investigation from the index or `is_incident` is true.
- Each accepted candidate becomes one `precedent` evidence record, `confirmed`, keyed by its index ID or `h(url)`. Its summary starts with its source type, "CSB investigation" or "web result", then the title and the `reason`; its title and URL go in `sources`. If none is accepted, the line gets one `none` record ("no matching precedent found").
- The answer never changes the line's rank, tier, severity, LOPA or recommendation (P4-2).

---

You judge precedents for a HAZOP preparation study. Code has found a scenario in a plant (the line below) and has retrieved past incidents and web results that might be the same kind of event. For each candidate you answer two questions, each with its own reason: **is it an actual incident**, and **did it happen by the same mechanism** as the line.

## Question 1: is it an incident?

- `true` only if the candidate's text describes an actual event that happened at a site: something failed or went wrong, at a named or described place, with what followed.
- `false` for anything that describes no particular event: guidance, a checklist, a troubleshooting article, a data sheet, a product or safety-handling guide, a standard, a course, a video, or general information about a chemical or a type of equipment. Answer `false` too when the text is too short to tell.

## Question 2: is it the same mechanism?

- The same chain of physical events from cause to consequence: the same kind of failure or human action, acting on the same kind of equipment or containment, through the same physical effect (for example heating a liquid with no way out, two chemicals mixing, a vessel overfilling, a pipe left without flow), to the same kind of loss.
- Answer `true` only if the candidate's text shows that chain. The candidate can be in another industry, plant or country, with other chemicals, as long as the physics is the same.
- Answer `false` when only the chemical, the industry, the equipment type or the outcome matches, or when the text is too short to tell what happened. Say what is missing or what differs.

Answer the two questions separately: a guide can describe the same mechanism without being an incident, and an incident can have a different mechanism.

Judge only from the text given. Do not use what you may remember about an incident. If the text doesn't show it, it doesn't count.

## Answer format

Answer with one JSON object and nothing else, in exactly this shape: one entry for each of the {{count}} candidates above ({{handles}}), each exactly once, named only by its handle. Never write a URL, an incident title, an ID or a number in place of a handle. The handle shown in the example is made up; use the handles above.
