# Feedback log: Token Factory, AI Cloud and NVIDIA models

Kept from day 1 for the hackathon's feedback submission. One row per friction point. Add a row the day it happens.

| Date | Tool | What happened | What would help |
|---|---|---|---|
| Kill tests (before 2026-10-12) | Token Factory API | Calls made with the wrong key returned a bare 401, with nothing to show which key or project was wrong. | An error body naming the key's project (masked) or saying "key not found" vs "key lacks access to this model". |
| Kill tests (before 2026-10-12) | Nemotron models via Token Factory | Answers were cut off at the token limit, often mid-JSON, after long reasoning used up the budget. | A documented way to cap reasoning separately from the answer, and clear guidance on `finish_reason: length` with reasoning on. |
| Kill tests (before 2026-10-12) | Nemotron outputs | Unicode hyphens and dashes (and non-breaking spaces) in answers broke plain keyword scoring. | An option for ASCII-normalised output, or a note in the docs that outputs may contain typographic Unicode. |
| Kill tests (before 2026-10-12) | Nemotron 3 Nano | Very slow on some prompts because of very long reasoning before the answer. | A reasoning-off switch documented per model, and per-model guidance on expected latency with reasoning on. |
| Kill tests (before 2026-10-12) | Token Factory catalog | Models were deprecated from the catalog with no automatic rerouting; calls by the old ID simply failed. | Deprecation dates in the model list, and an alias or redirect to the successor model for a grace period. |
| 2026-10-13 | Nemotron 3.5 Lightning, Nemotron 3 Ultra (smoke T3, T4) | With reasoning on, a strict `json_schema` (Lightning) or `json_object` (Ultra) request returned plain-text reasoning ("Here's a thinking process: …") in `content` instead of JSON, until the token limit. No `<think>` tags and no `reasoning_content`, so the reasoning cannot be separated from the answer. | Enforce the schema on `content` whenever `json_schema` strict is requested, or always route reasoning to `reasoning_content`; document which models honour strict schemas with reasoning on. |
| 2026-10-13 | Nemotron 3 Nano 30B (smoke T2) | "Reply with the word OK" billed 166 output tokens for `content` " \n OK", with no reasoning returned anywhere. | Return the reasoning (or report reasoning tokens separately in `usage`) so billed tokens can be accounted for. |
| 2026-10-13 | Token Factory, `reasoning_budget` (smoke T6) | Accepted on Ultra and Super with no visible effect on a short prompt, and no documentation of what it limits. | Document `reasoning_budget` per model, and report reasoning tokens in `usage`. |
| 2026-10-13 | Token Factory model list (smoke T1) | Helpful: every entry has a `shutdown_date` field (empty today), so retirements can be detected in code. | Fill it in ahead of retirements, and add per-model prices and context length to the same list. |
| 2026-10-15 | Nemotron 3.5 Lightning (gateway check) | With `tools` and a strict `json_schema` in one request (reasoning off, `tool_choice: auto`), the model never called the tool: it returned schema JSON with placeholder values (`"verdict": "rejected", "reason": "unknown"`). The specialist path needs two requests instead. | Allow a tool call when `tools` and a strict `response_format` are both given (apply the schema to the final answer), or document that strict schemas suppress tool calls. |
| 2026-10-15 | Nemotron 3 Ultra and Super (gateway check) | A one-line schema answer billed 420 (Ultra) and 290 (Super) output tokens with reasoning on, against 34 on Lightning and 20 on Nano with reasoning off; the reasoning tokens are billed as output. | Report reasoning tokens separately in `usage`, so a caller can see what a short answer really cost. |
| 2026-10-16 | Nemotron 3 Ultra (case D severity) | With reasoning on, a severity batch of 20 spent up to ~11k characters of reasoning and was cut off at 4096 output tokens; 6 of 7 calls were unusable and still billed. | A way to cap reasoning tokens separately from the answer, or to see how many of `max_tokens` the reasoning used. |
| 2026-10-16 | Nemotron 3.5 Lightning (case D specialists) | Of 69 failed batches, 27 named failing components that were not in the context (`operator`, `procedure_step`, invented instrument and loop IDs) and 20 were cut off at 6144 tokens; Super failed 8. Part of this was our cause list offering causes the context could not support. | Stronger adherence to an enum or ID list given in the prompt; strict `json_schema` with an ID enum would help if it combined with long outputs. |
| 2026-10-16 | Cause library (R46) | C10 "regulator" has no plant object kind in the schema and no dev plant has one, so it can never be offered; C08 "loss of power" needs a `power` utility and none of the five dev plants lists one, so common-cause power loss across several pumps, a classic HAZOP finding, cannot be raised. | A regulator object kind (or folding C10 into control valves) and power utilities in plant files. |
| 2026-10-16 | Token Factory prompt caching, Nemotron 3 Ultra (case H plant_screen) | Two calls whose request shared its first 89% with an earlier call came back with `cached_tokens` 4352 (17 blocks of 256) of 5295 and degenerate answers (1 hypothesis with an unknown ID, then 0); the reasoning said there was no plant record, although the plant block sat inside the cached prefix and was billed. The same request with a unique first line (`cached_tokens` 0) gave 12 valid hypotheses. On the D and G dev runs, specialist calls with a cached prefix were not ok 32 of 58 times against 370 of 739 without, so no clear effect there. | A way to turn prefix caching off per request, or `cached_tokens` and the cached prefix's boundary reported in a form we can check; and confirmation of whether a cached prefix is meant to change what the model attends to. |
| 2026-10-21 | Nemotron 3 Ultra (connector, `connector/v1`) | Asked to link chains by exact finding IDs (46–94 characters, two 16-hex hashes each), Ultra shortened or rewrote them: on case G all 36 bad finding links were damaged copies of IDs it was shown (hash parts dropped), and on case F two had the first 8 hex characters right and the next 8 invented. It also used bare object IDs and fields the plant does not have as fact links. The input was 20–25k tokens and nothing was trimmed. Code rejected every such chain: F kept 0 of 3, G 0 of 10 (D and E kept 10 each). | Long opaque IDs are not copied reliably. Short handles (`L1`, `P1`) that code maps back exactly avoid it (`connector/v2`). A copy-exactly mode, or constrained decoding over a given list of IDs, would help. |
| 2026-10-21 | Nemotron 3 Ultra (chain severity, `severity_chain/v1`) | Sent 10 chains in one call (about 9,000 input tokens; 5–15 links each, IDs up to 609 characters), Ultra rated only the last two. Its reasoning opened "We are given multiple chains (the last batch includes two chains)": it took the tail of one long list for a separate group, because the prompt called the list "the batch". The answer was valid JSON with `finish_reason: stop`, so nothing flagged it but the count. | Smaller calls, handles instead of long IDs, no group words for one list, the exact count stated, and code checking the answer count with one re-ask for the missing items (`severity_chain/v2`). A model-side "answer every item" constraint, or structured-output support for a fixed item count, would help. |
| 2026-10-21 | Nemotron 3.5 Lightning and Nemotron 3 Super (specialists, demo plant) | Batches of 5 questions were cut off at `max_tokens` 12,288, in two different ways. Lightning used no reasoning and wrote over 40,000 characters of answer, with many findings per question, and was cut off mid-answer (15 calls). Super spent 10,128 of the 12,288 tokens reasoning and was cut off just before its answer's closing brace (2 calls). Each such batch failed whole, so reboiler B's own section had no findings. | Re-asking a cut-off batch one question at a time (`retry_failed_batch_singly`). A separate cap on reasoning tokens, or answer-length guidance honoured by the bulk model, would help. |
| 2026-10-22 | Nemotron 3 Ultra (connector) and Nemotron 3 Super (specialist, hard) | On the final WG demo run, two English answers ended with CJK characters, both with `finish_reason: stop` and a valid schema: a chain description ended "…that互" (U+4E92, Ultra) and a finding's consequence ended "…release of hot水。" (U+6C34 and U+3002, Super). Nothing in the prompts or the plant data is in Chinese. The text is stored as returned and now flagged on the card. | A guarantee that output stays in the prompt's language, or a documented option to restrict output to a script, so a stop-terminated answer can't end with a stray token from another language. |
| 2026-10-22 | Nemotron 3 Ultra (`lopa_argument/v3`) | Prompt v3 says valve states are code's, not the model's. On the final WG run Ultra still argued a relief layer "does not apply" because "RV-PATH-EA425B requires inlet valves HV-B-SIN/HV-B-SOUT open" (one chain), so the record shows Ultra's "does not apply" where code alone would say "no credit — inlet valve HV-B-SIN closed". | Stronger instruction-following on "don't judge X" scoping, or a way to mark input fields as "given; do not re-derive". |
| 2026-10-22 | Nemotron 3.5 Lightning (specialists, bulk) | On the final WG run, 23 of 43 bulk batches of 5 questions failed: 13 cut off at `max_tokens` 12,288, 3 answered a question twice, 1 answered a question not in its batch, and 6 broke a validation rule (for example, an operator cause naming no procedure step). Of 173 bulk calls, including one-at-a-time re-asks, 47 were valid, 94 invalid and 32 truncated. Code re-asked each failed batch one question at a time and then at Super, so coverage held, but the cost moved up a tier. | Steadier schema compliance on lists (each ID once, only the IDs given) and shorter answers at the same `max_tokens`, or a way to cap the number of list items per answer. |
| 2026-10-22 | Tavily search (evidence step, final WG run) | The code-built queries (cause words, chemical names, equipment types) returned mostly generic pages: safety data sheets, fire-protection guides, response guidance, and once a page about anaesthesia. The precedent judge rejected all of them. | A search mode or parameter that favours incident and investigation reports for a technical query, or a topic/domain filter for safety-incident sources. |
