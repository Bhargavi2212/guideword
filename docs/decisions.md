# Decisions

| Date | Decision | Reason |
|---|---|---|
| 2026-10-11 | LOPA values (initiating events, protection layers, modifiers, tolerable frequencies) come from EGPC-PSM-GL-015 (2022), which tabulates CCPS typical values. | Free, public and citable; the CCPS books themselves are paid. Values cross-checked against Crowl & Louvar via the University of Michigan tutorial. |
| 2026-10-11 | Default tolerable frequencies use the EGPC typical TMEL levels (1e-2 to 1e-6 per year for S1–S5), not UK HSE R2P2. | R2P2 gives individual-risk boundaries for people, not per-scenario LOPA targets; the TMEL table maps directly to severity classes. Companies load their own. |
| 2026-10-11 | Severity class definitions are a Guideword default (people safety), labelled as such and editable. | No free public source defines the classes; EGPC defers to a corporate matrix. |
| 2026-10-11 | Tennessee Eastman simulator: use the open-licence Python package `tennessee-eastman-profbraatz` (University of Illinois licence, permissive; pure-Python backend; 20 disturbances; open and closed loop). | Licence permits use, modification and redistribution with attribution; no MATLAB needed. Rejected: pyTEP (needs licensed MATLAB and Python 3.7), tep-rust (no licence). Attribution and the Downs & Vogel / Braatz citations go in the README. |
| 2026-10-11 | DEXPI importer moves to "next". | No public Tennessee Eastman DEXPI example file could be found; the earlier claim that the DEXPI spec ships one is unconfirmed. |
| 2026-10-11 | Reactive groups: CAMEO group names and IDs for classifying chemicals; group-pair hazards to come from the EPA 1980 compatibility chart (EPA-600/2-80-076). | CAMEO offers no bulk download of its pair matrix. The EPA chart is a full public matrix; it still needs transcription from the PDF. |
| 2026-10-11 | Video script moves from Phase 0 to Phase 1, due Oct 15. | Bhargavi's call: Phase 0 stays foundations only. Still written before the frontend screens, so the screens are built for the video. |
| 2026-10-11 | Phase 0 runs Oct 12–14 with G1 on Oct 14 morning; Phase 1 runs Oct 14–15. | Oct 13 was overloaded (schema, loaders, dev cases, contract, G1) and everything depends on the schema finishing first. |
| 2026-10-11 | One bootstrap commit on `main` (docs and config only), then branch protection or a pre-commit hook. | "Never commit to main" and "CI green on main" cannot both hold on an empty repo. |
| 2026-10-11 | Frontend on Node 22 LTS. | Node 20 reached end of life in April 2026. |
| 2026-10-11 | Plant schema redesigned (PROJECT §9): instruments, logic solvers, valves, line components, heat sources, structured relief discharge, safeguard component IDs, procedure kinds, work time windows, fact IDs. | The earlier schema could not support the independence check, section splits, dead legs, the Williams Geismar heat-source case, physics calcs or overlapping-work questions. It freezes at G1, so it had to be fixed now. |
| 2026-10-11 | Reference tables restructured: applicability lists only applicable rows; causes carry `failing_component_type`; protection-layer credit conditions are structured columns; `modifiers.csv` keyed; `risk_matrix.csv` split into severity, tolerable and likelihood tables. | Code must apply credit and independence rules; ~2,100 yes/no applicability rows were unmaintainable. |
| 2026-10-11 | Outside-library causes: code assigns the highest frequency among library causes with the same failing-component type, else 0.1/yr, flagged "frequency assumed". | A model must never choose likelihood. |
| 2026-10-11 | Chemical questions: n(n−1)/2 pair questions plus a separate list of 3n environment questions (water, air, heat), counted separately. | The earlier "45 pairs" wording mixed the two lists. |
| 2026-10-11 | One $25 budget split by environment in the ledger: laptop $19, hosted $6; dashboard balance checked weekly. | Laptop and Vercel spend must not each assume the full $25. |
| 2026-10-11 | Run caps in `config/caps.yaml`; starting values LOPA on top 10, evidence on top 5. | No "top N" values existed. |
| 2026-10-11 | Vercel runs advance one step per invocation via `POST /internal/runs/{id}/advance`; the UI polls. | Hobby plan stops functions at 300 s. |
| 2026-10-11 | G2 tests 5B (core): question list, orchestrator, specialists, risk-matrix ranking. Connector and LOPA are checked on D–H after Phase 3. | Connector and LOPA are not built until Phase 3. |
| 2026-10-11 | Precedent search excludes the case under test and the demo plant's own report. | Williams Geismar would otherwise cite its own CSB report. |
| 2026-10-11 | The case writer creates and owns `guideword-heldout`; Bhargavi is invited only in Phase 6. | If Bhargavi creates the repo she owns it and can see the cases. |
| 2026-10-11 | Kill test #1 ran on tep-rust (no licence). None of that code is reused; the project uses `tennessee-eastman-profbraatz`. No Operon code. To be confirmed by Bhargavi from her machine in Phase 0. | Licence and Operon separation. |
| 2026-10-11 | PENDING Bhargavi's OK: `openapi-typescript` as a frontend dev dependency to generate TypeScript types from `contract/openapi.json`. | Keeps frontend types identical to the frozen contract; hand-written types drift. |
| 2026-10-11 | EPA 1980 chart transcribed: 41 groups, 303 pairs, from the one-page chart Bhargavi supplied (Texas A&M link is dead). `reactive_groups.csv` gains a `do_not_mix` column, set only for group 107. | The chart marks 107 "do not mix with anything" instead of listing pairs; a column keeps that rule in data rather than code. Header changed before the G1 freeze. |
| 2026-10-11 | A pair missing from the EPA chart is reported as "not listed", never "compatible". | The chart's own note says blanks do not mean a mixture is safe. |
| 2026-10-11 | Per-run spend cap lives only in `config/caps.yaml`; removed from settings and `.env.example`. | One value, one place. |
| 2026-10-11 | Each environment enforces its own allowance: laptop $19 in `budget/ledger.jsonl`, hosted $6 in the `spend_ledger` table; neither reads the other; weekly dashboard reconciliation. | The Vercel filesystem is read-only, and the laptop cannot read the hosted database. |
| 2026-10-11 | Test network block allows loopback; pre-commit hook is a POSIX `sh` script that refuses when `.venv` is inactive. | asyncio on Windows needs a localhost socketpair; Git for Windows runs hooks with `sh`. |
| 2026-10-11 | `_kpa` is always gauge, `_kpaa` absolute; vapour pressure is `vapor_pressure_kpaa`. Added `_per_year` suffix. | No hidden exceptions in unit conventions; a gauge/absolute mix-up is a ~101 kPa error in overpressure calcs. |
| 2026-10-11 | Optional `lines.length_m` and `planned_work.lifts_per_year`. If missing when a `per_metre_year` or `per_lift` cause needs them, the LOPA record is incomplete and names the fact; never a default frequency. | C20 (pipe leak) and C24 (crane drop) are not per-year frequencies. |
| 2026-10-11 | Plant IDs match `^[A-Za-z0-9][A-Za-z0-9_-]*$`; `.`, `:`, `~`, `+` are reserved for derived IDs. Section IDs survive renames. | Fact and question IDs use those characters as separators. |
| 2026-10-11 | Every record ID is built from content (`PROJECT.md` §11); never random, never a hidden counter. | Cache hits, replays and the trail must be stable. |
| 2026-10-11 | Overrides on a recorded run return 403; demo-mode accept/reject stays in the visitor's browser. | One judge must not change what the next sees. |
| 2026-10-11 | `openapi-typescript` approved as a frontend dev dependency. | Frontend types generated from the frozen contract. |
| 2026-10-12 | Finding ID includes cause and failing components: `f:<question>:<tier>:<cause>:<h(components)>`. | A question can have several causes; LOPA is per cause. The earlier `f:<question>:<tier>` allowed only one. |
| 2026-10-12 | Tool call ID includes the agent step. | `check_coverage` repeats with identical arguments and different results. |
| 2026-10-12 | Identical run inputs resume an unfinished run; after a finished, cancelled or failed run they start attempt `:<n>`. | Otherwise a cancelled run could never be restarted and benchmark cases could not be repeated. |
| 2026-10-12 | Events are identified by (run ID, seq), not a content ID. | The same record can be reported twice (cached call reused); events are not part of the replay comparison. |
| 2026-10-12 | Plan before code: each phase starts with Claude Code's `specs/phase-N-plan.md`, approved by Bhargavi. | Catch spec conflicts and drift before code exists. |
| 2026-10-12 | Plant data: methylhydrogen siloxane (Si-H) fluid is classed EPA group 105 (strong reducing agents); §9 example sets `SIH.epa_groups: [105]`. Source: the fluid's SDS (reacts with bases to release hydrogen) plus CAMEO group 35 (hydrides and silanes). | With no EPA group, KOH + Si-H returned "not listed"; as 105 it hits the chart's 105 × 106 row (GF, GT). |
| 2026-10-12 | §5 worked example: `reactivity_lookup` returns "flammable gas (GF), from the EPA chart", not "hydrogen release". | The tool reports what the EPA chart says, not a chemical name. |
| 2026-10-12 | `reactivity_lookup` moves from Phase 4 to Phase 2; the chemistry agent has it at G2. | Case G (a chemical pair) is a G2 pass case, and the tool is a pure table lookup. |
| 2026-10-12 | Added `reference/risk_matrix.csv` (severity_class, likelihood_class, rating, source; 25 rows; S + L: 2–4 low, 5–6 medium, 7–8 high, 9–10 very_high; Guideword default). Screening likelihood = the band holding the cause's initiating frequency (code). Code looks up tolerable frequency and rating. | The S × L grid was lost when `risk_matrix.csv` was split on Oct 11. |
| 2026-10-12 | Added a Recommendation record (action, reason, target), ID `rec:<finding or chain id>:<h(normalised action text)>`; overrides accept, reject or edit it. | Overrides need a target ID; recommendations had no record. |
| 2026-10-12 | Relief credit: `protection_layers.csv` gains `relief_kind` (prv → IPL-PRV, rupture_disk → IPL-RD, prv_with_disk → IPL-PRV-RD, vent → IPL-CONS-VENT). Every relief device is a candidate layer for overpressure on its `protects_id` without a safeguard row. Inlet closed → no credit; open and not locked ("unmanaged") → `pfd_if_isolatable`; all locked open or none → `pfd`. LOPA test: Williams Geismar, inlet closed, gets no credit. | Relief devices had no path to LOPA credit, and "unmanaged" was undefined; this is the demo moment. |
| 2026-10-12 | Chemicals gain optional `density_kg_m3`, `heat_capacity_kj_kg_k`, `vapor_pressure_points` (list of temp_c, pressure_kpaa); `vapor_pressure_kpaa` and `vapor_pressure_at_c` removed (supersedes the Oct 11 single-point field). Code interpolates (Clausius–Clapeyron), never extrapolates; missing data = calculation skipped and flagged. Suffixes `_kg_m3`, `_kj_kg_k`, `_usd` added to §9. | Heat-up rate and pressure-vs-temperature need these, and the schema freezes at G1. |
| 2026-10-12 | Added a `utilities` block (id, kind, location_id); `lines.from_id` / `to_id` may be utilities; `lines.is_hose` added. Failing components: utility cause → utility ID; hose → line; operator → procedure step or planned job; external → location. `failing_component_ids` is never empty. §9 example steam line now runs UT-STEAM → MX-1. | Utility, hose, operator and external causes had nothing to point to. |
| 2026-10-12 | Sections belong to the plant (status uploaded / sections_proposed / sections_confirmed); `sections_proposed` and `sections_confirmed` removed from run status. A run starts from a snapshot of confirmed sections; run setup = validate snapshot → build questions. Super's section-suggestion call has `section_suggest_cap_usd: 0.05` and is logged to the ledger. | Sections are confirmed through plant endpoints before any run exists. |
| 2026-10-12 | Unsure is a confidence, not a question status: the question stays `answered` (checked); coverage shows the unsure count separately; unsure findings may go to Ultra up to the cap, do not block `finish`, and are flagged in the shortlist. | `check_coverage` reported "unsure" but the status enum had no such value. |
| 2026-10-12 | Engineer questions: `POST /runs/{id}/questions` (section_id, text), origin `engineer`, ID `eng:<section>:<h(text)>`, status open. Running run: treated as any open question. Finished run: open until the engineer uses the new override action `answer`. | Origin `engineer` existed but nothing could create such a question. |
| 2026-10-12 | Procedure guidewords are the five in PROJECT.md (skipped, wrong, early, late, out_of_order); the `before` and `after` procedure rows are deleted from `applicability.csv`. Procedure rows only supply the `proc:` guideword list; procedure sections get no `m:` questions. | PROJECT.md and the table disagreed (5 vs 7); `out_of_order` covers sequence. |
| 2026-10-12 | Every equipment item gets its own section, all types. Pumps, compressors, heat exchangers and control valves split lines. | "Major vessel" left pump and exchanger applicability rows unused and counts undefined. |
| 2026-10-12 | No-flow line sections get the pipe matrix questions and their `nf:` question. Planned-work sections get only `work:` questions and have no section type. | Exact question counts in Phase 1. |
| 2026-10-12 | `dust:` fires for every `solids_handler` or `dryer`, plus any equipment containing a chemical with `combustible_dust: true`. | "Solids-handling equipment" was undefined. |
| 2026-10-12 | "Within reach" of a job = its `equipment_ids`, every equipment item in its location, every line with `from_id` or `to_id` in its location, and every other job at that location with an overlapping time window. | `work:` question counts were undefined. |
| 2026-10-12 | The coverage report counts every list: sections, matrix, chemical pairs, chemical environment, no-flow lines, procedure steps, jobs, dust, relief, engineer-added. | §5 Step 8 omitted environment and dust. |
| 2026-10-12 | No separate overpressure question: an `m:<section>:more:pressure` finding in the top N gets a `physics_calc` multiple-of-design in its evidence when the facts allow. | Overpressure had no question kind or ID. |
| 2026-10-12 | §9 example corrected: MX-1 `design_pressure_kpa` 350, PSV-1 `set_pressure_kpa` 350. | 101 kPa was a gauge/absolute slip, leaving the relief set above design. |
| 2026-10-12 | Budget by use and environment: laptop $19 = development 5 + test_5 4 + benchmark 8 + video 2; hosted $6 = demo_recording 1 + judging 3 + buffer 2. Ledger lines carry a required `use`; `live_call.py` refuses a call that would push a use past its allowance. | The use-to-environment mapping summed to 20 / 8, and use allowances were not enforced. |
| 2026-10-12 | Cache homes: `response_cache/` stays a git-ignored local cache; committed replay fixtures go to `bench/replay/<case>/`; the recorded demo run export to `cases/demo/recorded/`. No keys in either. | The CI replay test and demo mode need committed cached responses. |
| 2026-10-12 | `-e .` added to `backend/requirements-dev.in`. | `pip-sync` uninstalls anything not listed, including the package itself. |
| 2026-10-12 | `budget/ledger.jsonl` is git-ignored; Bhargavi commits `budget/ledger-<gate>.jsonl` at each gate. | A ledger committed on task branches diverges and conflicts across branches. |
| 2026-10-12 | Connector input = one-line finding summaries (ID, cause, consequence, components) plus the plant, never raw answers; `connector_max_input_tokens: 80000` in `caps.yaml`. | Keeps the connector inside the $1 run cap. |
| 2026-10-12 | Smoke test T14: one Ultra call with ~100k tokens of harmless filler, `max_tokens` 50, records acceptance and cost (≈ $0.10). Phase 0 cap raised from $0.50 to $0.65. | The long-context assumption was untested. |
